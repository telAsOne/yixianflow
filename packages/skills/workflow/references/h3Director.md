# A9.3 · H3 中文提示词与运镜适配

用于实际目标为 MiniMax H3 或 `yixian-h3-u06`、`yixian-h3-u08`、`yixian-h3-u00n` 的制作、修订与画布写入。先执行主 `SKILL.md` PART A 的剧情保真、节拍、估时、空间状态、表演、运镜、稳定性及 A11/A12 优化规则；本文件只适配 H3 协议，不建立第二套剧情优化方法。Seedance 模板、段长与引用命名不直接用作 H3 执行参数。

## 真实能力与中文正文

- 通过实际工具发现目标节点及 `node:getConfig`，核实 provider/model、时长、分辨率、画幅、参考模式、音频和原生声音能力。以本次配置为准，U06/U08/U00N 分开判断。
- 已确定的时长是约束，不因镜头增加自动延长；放不下时按 PART A 给出具体冲突与拆段方案，不删台词、不强行加速、不悄悄多生成。
- 规划、主体定义、剧情、动作、运镜、环境音及优化后正文保持中文；原台词逐字保留原语言。英文协议字段名、编号和标签保持原样。
- 不把本适配当成改服务器优化模型、系统提示词、运镜库、价格或自动生成设置的授权。需要优化时沿用当前已配置且实际可调用的流程，不自造接口或节点函数。
- 用户本次只要求画布分镜时，优化指本轮对文稿应用 PART A 的规则：只读必要资料并完善中文剧情与运镜。不修改服务器设置、节点生成参数，不调用服务端优化或生成接口。

## 六段执行正文

写入节点 `prompt` 时按以下顺序使用六段文本。完整剧本、总览、E## 账本、分析和采用记录保留在各自文稿，不混进可执行正文。

```text
subject_definitions:
本段实际主体的中文定义、真实参考映射与原有说话人关系。

summary:
[reference generation] 用中文说明本段剧情和时长。

retention_analysis:
真实参考需保留的身份、外观、物件、空间或声音特征及允许变化。

detailed_description:
本段共同的视觉、连续性与声音约束。
[Shot 1] 用中文描述起始状态、完整动作、原文对白与具体运镜。

overall_soundscape:
仅写源剧情已有或用户要求的实际环境与动作声。

non_diegetic_music:
没有配乐要求时为 N/A；已有要求按原文保留。
```

这是结构说明，不是要照抄进作品的内容。没有真实媒体时，参考专用的主体定义和保留分析可留空，文本角色仍在剧情里明确，不伪造参考标签。`summary` 任务前缀符合实际用途：`[reference generation]`、`[video editing]`、`[video continuation]`、`[audio reuse]`、`[audio reference]` 可按实际组合。仅有角色图不能称视频续写；前段视频被引用也不等于已成为连续帧引导。

服务端优化流程确实要求 JSON 时，才返回同名六字段对象：`subject_definitions`、`retention_analysis` 为字符串数组，其余四项为字符串。画布 `setPrompt` 写六段文本，不把 JSON 外壳、Markdown 围栏或私有优化规则贴进节点。

## 节拍、镜头和生成段分别处理

- **节拍**是说话、拿物、倒酒、反应等剧情进程，多个节拍可属于同一个镜头。
- **镜头**表示摄影连续性，只有真正切镜时才增加 `[Shot N]`。转头、伸手、倒酒、移焦或到达某个时间不自动变成新镜头。
- **生成段**是一次视频任务的承载范围，可包含一个或多个镜头；分批交付文稿不等于增加生成段。

用户写“同机位延续”“连续完成”“一镜到底”或明确不切镜时，先把时间块理解为镜内动作进程。若同时出现多个 Shot 标记，按明确连续性要求消解歧义：保留事件、顺序和时间安排，在一个 `[Shot 1]` 内描述各阶段。真实且明确要求的切镜仍保留；无法判定的冲突才指出，不自行新增剪辑。

单镜头可写“镜内约 6 秒开始倒酒”“随后完成举杯”，不要写成 `[Shot 2] At 00:06.000`，后者表达新切镜。保留分析等叙述中用“第 1 镜”等普通文字引用，不反复使用协议标题。

实际多镜头时，首标题为 `[Shot 1]`，后续标题各自独立起段，使用 `[Shot 2] At 00:06.000,` 等格式；时间严格递增且小于所选段长。时间是生成引导，不承诺指定帧精确切换。每次切镜应有叙事视角或信息呈现理由，不用切镜掩盖手部接触、道具状态或动作过程缺失。

## 运镜落到具体画面

用户需要创作分镜、电影感或把模糊的摄影意图写具体时，可按需查[镜头设计表达](methods/h3ShotDesign.md)，取用观看顺序、动作与摄影分离、材质和光色的表达方法。它只补导演表达，不另定剧情、镜头数、生成段长或H3外壳。

先确定要让观众看清什么，再按 PART A A7 选择必要的摄影方法。固定机位和单一缓慢运动都可以成立，不强制每镜运动或使用预设。

将运镜与当前动作写在同一镜头的自然语言里，交代：

- **起点**：相对主体的机位、机身高度、拍摄方向、初始景别和主体在画面的关系。
- **对象**：跟随人物、手、道具或已有的视线变化，保持什么清晰入画。
- **路径**：摄影机向哪个方向位移、沿什么轴线或围绕哪个实际主体运动；不把人物移动当成运镜。
- **节奏**：何时开始、平缓还是加速、关键动作处是否减速或停稳。同一时段以清楚的主要运动为主，复杂组合只在用户要求或实际表达需要时采用。
- **落点**：最终景别、构图和关注对象，与下一动作或合法下一镜如何承接。

推轨推进改变机位和透视，变焦改变焦距；摇摄改变朝向，横移改变位置；升降和俯仰也不能互换。确有要求且能力支持时才组合推拉变焦等复杂效果，不把不同术语堆成“高级运镜”。不编造器材型号、不可核实的精确轨道距离或无用途的参数。

双人对话、递物或倒酒时，保持视线、交互的手和道具有清楚的空间关系；不为推近裁掉关键接触却声称完整展示动作。连续镜头的落点由前面的运动到达，不突然恢复远景、切到另一侧或重置桌面构图。

例如，源剧情已明确“两人坐桌边，她倒酒后放下酒壶，两人举杯”，可写：

> 镜头从桌侧、接近人物肩部的高度拍摄双人中景，两人分居画面左右，酒壶和两只杯子清楚入画。倒酒过程中摄影机沿原拍摄方向极慢向桌边推进，始终保留两人的脸和倒酒动作；壶嘴离开杯口时逐渐减速，停在略近的双人中景。她按原动作放下酒壶，两人接续举杯，摄影机保持落点构图，不切镜、不重置机位。

此例只示范摄影表达；原文没有这些动作就不能照抄或新增。若原文要求固定机位，就保持固定，不添加示例的推进。

## 接入已有运镜库和优化流程

1. 按真实 schema 查询 `node:getConfig`。`cameraLibrary.supported` 为 true 且需要运镜库时，再查询 `node:getCameraPresets`。目录返回真实 `id`、`name`、`tag`；向用户展示名称，不猜 ID。目录为空或读取失败时说明实际缺项，可继续写中文运镜草稿，不编造标签或声称已套用库。
2. 保留用户已选运镜；未选时按本镜的对象、方向、路径和落点选择适合的真实条目，普通静态镜头不强插预设。
3. 将返回的原样 `{{CameraPreset ID}}` 放在 `detailed_description` 对应镜头，保留中文剧情、原对白和风格。不把标签放到全片开头使范围不清，不叠加与预设相反的自由运镜。
4. 私有指令由既有服务端展开与优化流程处理；不读取、复制或臆造私有模板，不用自己的改写替换预设。优化后标签可能正常展开，不把内部展开文本当作公开可复用模板。
5. 只有当前工具确有独立优化能力时才调用；没有时完成可写入的文稿和节点，不假称已运行优化。`node:setPrompt` 只改正文，不自动优化或生成；不得为取得优化结果偷偷调用 `generateVideo`。
6. 结果可读取时，依照 A11/A12 核对中文、原台词、镜头数、切点、时长、引用及运镜作用范围。若连续阶段被重新拆成切镜，或原动作和运镜意图丢失，修订受影响稿件并保留原版、差异；不自动重提付费生成。

摄影运动不授权添加电机、滑轨、旋翼、风噪、呼啸或转场声，只保留原剧情、明确声音要求及有依据的场景声音。中文要求落实在本轮画布文稿；服务端再次优化和成片质量不属于文稿验收，不能为保持中文修改后台设置。

## 引用、对白和写入复核

- 读取真实端口、输入和排序；H3 的 `<Picture N>`、`<Video N>`、`<Audio N>` 按各媒体类型分别编号，不直接等同混合媒体的 `{{ref N}}`。没有注册的 `getReferences` 不能虚构调用。
- 主体使用实际 `<Subject N>`，已有映射与说话人 `(S1)` 等绑定保持不变，不因主体列表重排交换角色和台词。原对白连同语言标签、标点和顺序逐字保留，例如 `<Subject 2> (S1) 说：<d>[Chinese]原文台词</d>`。
- 通过 `node:getConfig` 读取真实 `references.id`，再用 `node:setConfig.subjects` 登记主体的 `id/name/references`。同一人物的基础态与变体属于同一主体；同段引用多张形态图时，用 `referenceNotes` 按引用 id 逐项说明适用镜头与状态，不能让模型把它们融合或当成两个人。场景、道具和特效也在六段正文中按实际标签写清用途；只连线不算完成绑定。
- 旁白、内心声与画内对白分开，不为声音标签给不说话的人加口型。已有 `<scenetrans>` / `<cutoff>` 等协议标记按原义保留，不臆造音色样本。
- 缺必要素材、引用映射不确定或模式不兼容时，保留可读草稿与具体缺项，不伪装为已就绪。
- 按 [画布执行](canvasExecution.md) 通过真实 `node:setPrompt` 写入并回读，核对六段中文、引用和已选运镜。生成授权、结果采用与质量验收按原流程处理；写入成功不代表已生成或衔接已验证。
