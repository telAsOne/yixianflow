# 视频反解：从原片证据到可用成果

用于看懂视频、整理剧本、单维度分析、完整拉片、复刻和参考替换。先沿用用户的范围与目标；原视频是观察依据，类型经验不能补成原片事实。需要生成提示词时才编译正文，媒体生成授权仍按主文档处理。

## 按问题决定交付深度

| 本轮任务 | 应交成果 |
|---|---|
| 故事概括、人物关系、结局解释 | 可确认的事件顺序、关系与依据；动机推断与画面事实分开 |
| 整理为剧本 | 场次与时空、人物、连续行动、可靠对白/OS/VO、结果或转场 |
| 只分析镜头、光色、声音或指定时间 | 对应维度与必要关联证据，不展开无关全片报告 |
| 完整拉片、反解 | 全局视听特征、逐镜观察、镜内变化和交接状态；覆盖受限时明确范围 |
| 复刻、生成提示词 | 在反解基础上，给原片范围到目标生成段的对应及完整模型正文 |
| 换人物、服装、场景等迁移 | 原片分析与替换素材分开，只覆盖获准替换的维度，其余保持原片依据 |

“复刻”可以完成文稿，不自动调用付费生成。只问剧情时直接回答问题，不把工具日志、内部覆盖表或大段协议正文塞给用户。

## 先确认实际读取了什么

记录原片实际文件或附件、节点与输出版本、用户要求的时间范围、实际可读范围，以及取得元数据、画面和声音的方式。能取得的时长、分辨率、帧率与音轨来自媒体本身或真实探测；未知就记未知，不由封面或文件名推断。来源文件更换后，旧观察仍对应旧版。

当前宿主有两条路径，不能混同：

- 主动上传的视频附件进入模型的媒体处理路径；仍要确认实际返回的内容和能力范围，不能仅因上传成功声称完整观看或听清对白。
- `@` 视频节点或视频素材通常只提供快照路径。通过本轮真实可用的媒体工具读取或处理；节点名、路径、播放器和创建回执都不代表看过内容。视频拼接等纯文件操作不需要先声称理解剧情。

有实际启用的 `ffprobe`、`ffmpeg` 与图片读取工具时，可复用以下路径，不要求新造反解节点：

1. `ffprobe` 探测真实文件，确认本轮处理范围与媒体信息。相对路径以当前工作区为准；工具运行依赖实际选定的本地助手，未连接或工具不可用时说明具体条件。
2. 用 `ffmpeg` 按实际需要截取不同时间的帧、补看疑似切点前后和关键接触过程，保存新文件名后用图片读取工具实际查看。抽帧位置和连续读取范围如实记录；零散静帧不能证明中间动作、准确切点或声音。
3. 对需要辨认的快速动作或镜头边界，使用可用的连续视频读取，或增加附近取样。做不到时把该区间记为未确认，继续完成有证据的部分，不编造“已逐帧拉片”。

例如，工具确已提供这些 schema 时，可分别调用下列参数。路径是教学示例，使用前替换成实际存在的输入，输出换成未占用的新名称；每次截帧都要真正读取结果：

```json
{"path":"assets/input.mp4"}
```

```json
{"steps":[{"method":"input","args":["assets/input.mp4"]},{"method":"seekInput","args":[1]},{"method":"frames","args":[1]},{"method":"output","args":["assets/reverseFrame01.png"]}]}
```

第一段用于 `ffprobe`，第二段用于 `ffmpeg`。不虚构 `readVideo`、自动反解接口或隐藏参数；没有这些工具时按当前媒体能力完成可支持的分析。

链接输入要取得本轮工具确实能读取的视频本体或等价媒体。标题、封面、网页文字和元数据只支持对应信息；页面无法解析时简短说明未取得哪个视频或区间，并请求可读文件或直链。不能据封面交“全片反解”，也不执行未经授权的付费下载或转码方案。

## 声音单独取得依据

音轨存在只证明有音轨。对白、旁白、音乐、音效、静默和同步关系分别依据实际听取、可靠转写、字幕/OCR或用户提供文本记录，并保留来源差异：字幕不自动等于原声台词，转写不证明说话人、音色或混响，未提供声音不能写成原片静音。

听不清的词和说话人写待核实，不能补成“挑衅台词”并宣称完整复刻。只有画面没有声音证据时，不按动作自动添加脚步、衣料、碰撞、开门声或配乐。原片持续声音跨切镜或生成段延续，不在边界自行重启。用户允许重新设计声音时另列设计选择，不改写观察记录。

## 分开原片时间、摄影镜头与生成段

- 原片时间用于定位证据；抽取子片段后仍保留它相对原片的偏移。
- 只有实际剪辑切换才建立新镜号。转头、伸手、移焦、摄影机移动、遮挡及曝光变化可以发生在同一连续镜头；需要时为它们增加观察区间，并标“同镜，无切镜”。不能确认遮挡处是否剪辑就保留疑点。
- 按真实变化点细看动作、人物进出、视线、接触、构图、焦点、光影、声音和字幕。粒度服务于变化；不规定每三秒分析一次，也不以分析区间数量决定镜头数。
- 快切按实际次序和可确认时长逐镜保留；不能看清的镜头明示缺项，不用“快速蒙太奇”抹去它们。
- 生成段是目标模型的一次任务。段长由用户要求、剧情容量和实时能力决定，不沿用固定十五秒包装；一个连续镜头跨生成段时仍注明摄影连续性，不因任务切分增加剧情切镜。

## 用三层资料组织完整任务

第一层是来源与观察，第二层是全局和逐镜解释，第三层只在需要时编译为模型正文。三层可放在一份可编辑文稿内，不强制三套文件或新 JSON 格式。

完整拉片可用以下表保存原片依据；简短分析只取本次需要的列：

| 原片范围与证据 | 镜号及镜内区间 | 人物与动作、接触、结果 | 构图、摄影与可见光色 | 声音或文字及来源 | 区间末态与疑点 |
|---|---|---|---|---|---|
| 实际时间、取样帧/连续读取范围 | 真实切镜，或同镜的变化 | 谁施事、谁受事、谁持物，起点到结果 | 观察到的方向、速度、落点、焦点与材质响应 | 逐字可靠台词；未知单列 | 位置、姿态、动作相位、持物及未确认项 |

全局理解从这些观察归纳：媒介与画幅、主要身份与造型、空间关系、观看顺序、剪辑节奏、光色变化和有证据的声音模式。可推断“长焦观感、背景压缩”，不能断言拍摄器材、精确焦距、灯具数量或色温；不把不可见心理与背景设定写成事实。

段首段尾记录实际交接状态：人物世界位置、朝向、姿态、动作相位、持物与道具状态、摄影机位置和构图、环境及持续声音。需要衔接时，后一段从前一段实际末态开始；暂不可读的末态标未知，不以计划落点冒充观察结果。

例如在一个虚构观察中，原片 0–4 秒人物拿起杯子，4–8 秒把杯举到胸前，期间摄影机连续推进：这是同一镜头的两个动作区间。若只查看第 0、4、8 秒三张静帧，仍不能断言中间没有剪辑或杯子从未换手；需补读或限定结论。这是证据边界示例，不是当前用户视频的结果。

## 编译到 H3 或进行替换迁移

需要复刻提示词时，先列“源视频哪个范围 → 目标哪个生成段、段长、局部切点”。目标时长与原片节奏冲突时给出影响及拆段、延长或获准压缩的选择；不把三十秒动作挤成十五秒并称原样复刻，也不自行增加任务次数。

H3 正文交[H3 适配](../h3Director.md)与主 PART A：六段、中文主体内容、真实媒体标签、独立说话人及实际切镜。原片的全局视听特征合入本段需要的保留分析和详细描述，不把观察表、诊断、日志、来源覆盖清单或另一套反解标题贴进 `prompt`。每段独立说明必要身份、场景、动作和声音，不能只写“同上”。完整成稿示例见 [H3 完整示例](h3Examples.md)。

参考替换按[资产用途](../assets.md)明确“哪个真实素材 → 哪个对象和维度 → 哪一镜或时间 → 保持项”。只换服装就保留原片身份和动作；只借运镜就不顺带移植其人物与事件。使用真实图片时登记真实引用；只有文字交付且不会提供参考图时，写自包含描述，不伪造 Picture/Subject 媒体绑定。

## 根据实际完成范围交付

普通问题给直接结论及必要时间定位。完整拉片交全局说明、逐镜成果和具体缺项；复刻文稿再附源片到生成段对应、素材用途及完整模型正文。只有覆盖了全部约定范围及所需声音，才称完整视听反解；其余准确写“指定片段分析”“基于抽帧的画面分析”或“声音未核实”。

按用户要求保存到当前画布文本节点；明确只要对话文字时直接回复。必要的来源、版本与观察范围保留在现有记录，恢复和采用按[状态与交付](../stateAndDelivery.md)处理。反解完成、正文保存、任务受理、取得新文件及实际验收分别陈述；生成工具返回成功不能证明视频已完成或已查看。
