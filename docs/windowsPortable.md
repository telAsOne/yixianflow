# Windows 便携版

1. 将整个压缩包解压到 D 盘的可写目录，例如 `D:\toonflow`。
2. 双击 `toonflowPortable\toonflow.exe`。无需自行启动 Bun、Node 或本地服务。
3. 在设置中填写所用渠道的地址和密钥，再选择模型。交付包不包含密钥或用户数据。
4. 创建项目时选择 D 盘文件夹。关闭主窗口即可退出应用及其本地服务。

请完整保留目录结构，不要只复制 EXE，也不要直接在压缩包内运行。支持 Windows x64，需要本机已有 Microsoft Edge WebView2 Runtime 120 或更新版本。程序不自动安装系统组件，不注册卸载项、协议或快捷方式。

从 2.0.2 起，新安装仅预置文本供应商 `ds`（Anthropic 协议、`deepseek-flash`），以及老李生图、老李视频、Sub2API 生图三个媒体供应商。内置添加列表使用同一组供应商，自定义供应商入口保留。首次启动向导直接配置文本模型，不再提供 TF-Router 自动配置。升级保留已有文本配置、媒体模型列表与密钥，不再自动补入 TF-Router、APIMart、秘塔和优云智算；此前自行保存或导入的其他供应商不会被删除。「关于」页不再展示或请求赞助商信息。

## 数据位置

- `data`：配置、供应商、插件和生成任务记录。配置中可能包含 API 密钥，请勿上传或分享。
- `profile`：窗口页面的持久状态与 WebView2 用户资料。
- 项目目录：创建项目时自己选择的位置，保存画布、分镜与生成素材。
- `cache`、`temp`：应用自身的缓存与临时文件。
- `runtime`：随包提供的运行文件，不需要全局安装开发环境。

这些目录相对于 `toonflow.exe` 创建，应用只修改自身进程的环境变量，不修改系统 PATH。移动便携包前先退出应用；外部项目目录不会随包移动，移动项目后需重新打开它。

从支持在线更新的便携版开始，在「设置 → 关于」中使用「检查更新 → 下载更新 → 重启并更新」。更新源固定为 `telAsOne/yixianflow` 的公开 GitHub Releases，用户无需登录或填写 GitHub 凭证，旧设置中的其他更新源会被清理；发布者需要先上传便携更新包。尚未发布时会提示更新文件不存在，当前版本仍可使用。不要用官方安装包覆盖此定制版。

GitHub 更新请求在启动时读取 Windows 当前用户的系统代理；代理软件和端口由系统现有设置决定，不写死地址，也不修改系统配置或模型请求。调整系统代理后请重新打开应用。

更新前保存正在编辑的内容，等待生成任务结束。下载、校验期间可以继续使用当前程序；点击重启后才替换 `runtime` 和顶层 `toonflow.exe`。`data`、`profile`、项目目录保留，三个内置媒体供应商同步适配代码时保留用户编辑的模型列表及独立配置，其他供应商保持原样。手动改过受管理供应商的函数代码需要自行备份。

更新文件放在 `cache/updates`，更新助手放在 `temp`。下载中断或校验失败不会替换程序，可重新下载；新版未在两分钟内完成启动时尝试恢复旧程序并重新打开。确认新版启动成功后清理本次旧程序、下载归档及临时助手。回退后显示具体失败原因，同一失败构建保持拦截，发布者提供不同构建后可继续检查更新。失败归档和暂存目录保留用于恢复与诊断；若自动恢复也失败，不要删除备份。

旧的 2.0.0 便携包没有更新交接功能，需要最后一次手动替换 `runtime` 和 `toonflow.exe`（下方步骤），之后再使用应用内更新。更换版本前仍建议备份 `data`、`profile` 和项目目录。

首次真实生成需要另行确认内容和费用。视频选择完整型号 `特价2.5需要过人脸技术-可参考过人脸素材库`，建议先做 16 秒、720p、单角色、单场景。图片和文字模型各自收费；本轮交付只进行模拟验证。

## 从源码构建

复用项目锁文件要求的 Bun 与 Electrobun，先将 `TEMP`、`TMP`、`HUTCH_HOME`、Bun 缓存目录设置到 D 盘。依赖保留在项目 `node_modules`。

```powershell
$env:appVersion = "2.0.2"
bun run build:desktop
bun apps/desktop/scripts/packagePortableWindows.ts D:\rubbish\zhongjian\artifacts\toonflow\新的版本目录
```

第二步只使用第一步生成的本地归档，拒绝覆盖已有产物目录。编译器使用 Windows 现有 .NET Framework C# 编译器，解压缩使用 Windows 自带 tar；不调用 NSIS，不安装工具。

除了可直接运行的 `toonflowPortable` 目录和 `toonflowPortable.zip`，还生成独立的 `stable-win-x64-portable-update.json` 和 `stable-win-x64-toonflowPortable.tar.zst`。发布更新时，两个文件须来自同一次打包，并上传到同一个 GitHub Release；版本号须递增。清单包含便携版标识、压缩包长度与 SHA-256，启动器也计入构建号，客户端不接收安装版更新包。默认分支的代码推送会触发下方的自动发布流程，发布成功后软件才能发现更新。

## 在 GitHub 自动发布便携版

工作流文件为 `.github/workflows/releasePortable.yml`。向 `master` 推送代码后，自动取当前正式版本并递增末位编号，例如 `2.0.2 → 2.0.3`；无需修改源码版本号、创建标签或点击发布按钮。版本记录按每页 100 条读取，仅保留当前主次版本的最大补丁号，跳过已有版本和失败草稿占用的编号。

1. 先将准备发布的修改推送到 GitHub 默认分支。
2. 在「Actions → 发布 Windows 便携版」查看构建进度。
3. 流程成功后，新的 `portable-vX.Y.Z` Release 以 `Yixianflow X.Y.Z（Windows）` 为名称并自动设为最新版，软件用户自行点击检查更新。

只有 `docs/`、根目录 `README.md` 或 `AGENTS.md` 的修改时跳过发布；`packages/skills/` 等随程序分发的 Markdown 文件仍会触发发布。已发布的当前提交重复运行时跳过，开始处理前发现分支已有更新提交的旧任务也跳过。发布流程串行执行，正在运行的任务不会被新 push 取消；GitHub 可能合并等待中的多次 push，最终处理最新提交。

需要手动重跑或指定主次版本时，仍可在同一工作流点击「Run workflow」。版本号留空自动递增，也可填写高于正式版且未占用的版本号，例如 `2.1.0`，不带 `v` 前缀。无需额外提交版本号文件，流程生成的标签不会触发新的代码构建。

流程只构建 Windows x64，复用锁文件和现有便携打包脚本。GitHub 临时 Windows 运行器的源码、项目依赖、Bun/Hutch 环境、缓存、中间文件和发布产物使用 D 盘；无需在个人电脑安装工具、购买服务器或上传模型密钥。只有发布步骤获得 GitHub 自动提供的仓库写权限，不需要另配个人访问令牌。构建结果在 Actions 中保留 7 天，正式附件存放在 Releases。

类型检查、构建、包版本、归档长度和 SHA-256 校验通过后，先上传三个指定附件到草稿；远程附件校验通过才正式发布。仅发布便携包，不调用 NSIS 安装包脚本或上传到原版托管服务。自动流程不启动个人电脑上的程序，不替换本地 EXE，不调用模型，也不代替桌面交互验证。

构建或上传失败时，当前正式版保持可用。上传产生的失败草稿保留，后续代码 push 或自动编号任务的「Re-run all jobs」会重新选择未占用版本，无需先删除草稿。手动指定相同版本、已有标签或草稿仍会被拒绝，不覆盖正式版本。请使用「发布 Windows 便携版」工作流；仓库继承的「Release Toonflow」仍是原版多平台发布流程。

## Anthropic 对话修复版

本版本修复 `@earendil-works/pi-ai@0.85.1` 转换 Anthropic 工具参数时丢弃根定义的问题。补丁由 `patches/piAiAnthropicSchema.patch` 和 Bun 的 `patchedDependencies` 管理，保留 `definitions`、`$defs`、引用及原有约束，依赖版本不变。重装依赖时应使用锁文件，不能单独删除此补丁。

DeepSeek 使用 `https://api.deepseek.com/anthropic`、`anthropic-messages` 和 `deepseek-flash`；密钥仅在应用设置中填写。切换协议时须同时匹配地址：Chat Completions 使用根地址或 `/v1`，不保留 `/anthropic`。

更新已经使用的便携目录：

1. 关闭旧版 Toonflow，等待应用退出。
2. 将旧目录中的 `runtime` 改名为 `runtimeBackup`，保留回退副本；已有同名备份时使用新的备份名称。
3. 从新包复制 `runtime` 文件夹和 `toonflow.exe` 到旧目录。保留原来的 `data`、`profile` 和项目目录，不用新建空目录覆盖它们。
4. 双击旧目录中的 `toonflow.exe`，将文本供应商恢复为上面的 Anthropic 地址与协议，并保存。

只替换顶层 EXE 不会更新对话逻辑，必须同时更新 `runtime`。直接使用新包目录也可以，但该目录初始没有旧配置。

针对性模拟验证命令：`bun test apps/server/verification/anthropicSchema.test.ts --timeout 10000`。使用 SDK 的内存模拟响应，不读取真实密钥、不发网络请求、不写项目数据。覆盖三种协议的完整画布工具定义、默认与高推理参数、流式回复、工具结果回传、多轮对话、异常断流，以及 Anthropic 根约束与严格模式；14 项、303 条断言在 Bun 1.3.14 和包内同版 Bun 1.4.0 下通过。真实 DeepSeek 调用须另行确认。

修复版已从新 ZIP 解压启动，确认原生窗口响应正常，并通过 Chrome DevTools 操作同一桌面服务的界面。独立的本机 Anthropic 模拟接口接收 5 次请求，完成问候、高推理等级下的 `getNodeTools → nodeTools → 回复` 和下一轮对话；实际读取分镜的 16 秒设置，工具结果与对话记录正常保存，缺失定义错误为 0。验证使用单独的模拟配置，没有复制真实密钥，也没有调用生图、生视频。测试应用、模拟接口、监听端口和验证标签页均已关闭。
